# Fast & Slow Pointers — Question Bank

Micro-questions over [[04-fast-slow-pointers|the fast & slow pointers pattern]]. Answer in a full sentence before opening the toggle. Format explained in [[dsa/02-data-structures/01-arrays-qb|the arrays bank]].

## A. The idea

**1. Give the hallway analogy.**

<details><summary>Answer</summary>

One person walks normally, another runs twice as fast. **If there is a loop, the faster person eventually catches the slower one; if there is not, the faster person reaches the end first.**

</details>

**2. State the pattern.**

<details><summary>Answer</summary>

**Walk two pointers through a structure at different speeds** — one step versus two steps.

</details>

**3. What is it formally called?**

<details><summary>Answer</summary>

**Floyd's Tortoise and Hare algorithm.**

</details>

**4. What is lapping?**

<details><summary>Answer</summary>

**The fast pointer overtaking the slow one inside the cycle** — the faster runner lapping the slower on a circular track.

</details>

---

## B. Cycle detection

**5. Write the loop.**

<details><summary>Answer</summary>

```python
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow == fast:
        return True
return False
```

</details>

**6. Why is the guard `while fast and fast.next`?**

<details><summary>Answer</summary>

**The fast pointer takes two steps**, so both the current node and its successor must exist before moving. Checking only `fast` crashes on the last node.

</details>

**7. Why must they meet if a cycle exists?**

<details><summary>Answer</summary>

Once both are inside the cycle, **the gap between them shrinks by exactly one node every step**, so it must eventually hit zero.

</details>

**8. Trace `1→3→5→7→9→5`.**

<details><summary>Answer</summary>

slow: 1, 3, 5, 7, 9, 5…; fast: 1, 5, 9, 7, 5… **After 3 steps both are at node 5 — cycle detected.**

</details>

## C. Versus a hash set

**9. What is the hash-set alternative?**

<details><summary>Answer</summary>

Keep a set of visited nodes — `if node in visited: return True`. **Simpler to reason about.**

</details>

**10. Why is the pointer version worth knowing anyway?**

<details><summary>Answer</summary>

**Same $O(n)$ time with $O(1)$ space** instead of $O(n)$ — which is **the entire reason this pattern exists** rather than always reaching for a set.

</details>

## D. Beyond linked lists

**11. What does the pattern generalise to?**

<details><summary>Answer</summary>

**Any sequence generated by repeatedly applying a function to a value** — anywhere you can compute the next element deterministically.

</details>

**12. How does happy number use it?**

<details><summary>Answer</summary>

`get_next` is the sum of the squares of the digits. Run slow one step and fast two until they meet; **the number is happy iff the meeting value is 1.**

</details>

**13. How does find-the-duplicate use it?**

<details><summary>Answer</summary>

An array of length $n+1$ with values in $[1,n]$ — **treat array values as implicit `next` pointers.** A duplicate value means two indices point at the same place, which is a cycle.

</details>

**14. How do you find the cycle's *entrance*?**

<details><summary>Answer</summary>

After the meeting, **reset one pointer to the start** and advance both one step at a time. **They meet at the entrance.**

</details>

**15. Why does that work?**

<details><summary>Answer</summary>

By the distance algebra of the meeting point: the distance from the head to the entrance equals the distance from the meeting point to the entrance, **going around the cycle**.

</details>

---

## E. Trade-offs

**16. What does the basic algorithm not tell you?**

<details><summary>Answer</summary>

**Where the cycle starts** — only whether one exists. The entrance needs the extra phase above.

</details>

**17. What is the precondition?**

<details><summary>Answer</summary>

**A well-defined, deterministic "next" function.**

</details>

**18. When is the hash set preferable?**

<details><summary>Answer</summary>

**For small inputs, or when memory is not a concern** — it is clearer to reason about and easier to get right.

</details>

**19. What are the costs?**

<details><summary>Answer</summary>

$O(n)$ time, **$O(1)$ space**.

</details>

**20. Summarise the pattern in one sentence.**

<details><summary>Answer</summary>

Run two pointers at different speeds and let the faster one lap the slower — cycle detection in constant space, on anything with a next function.

</details>
