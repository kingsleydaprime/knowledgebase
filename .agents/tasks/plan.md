# Implementation Plan — Mark as Missed

## What was found

- `task_status` is a Postgres enum: `('pending', 'done', 'skipped', 'cancelled')`. `missed` is NOT in it.
- `events.status` is a text column with a CHECK constraint: `('upcoming', 'done', 'cancelled')`. Not an enum — ALTER TABLE to add `'missed'` to the check.
- `xp_reason` enum has: `completion`, `late_completion`, `ignored_need`, `goal_completion`, `wish_fulfilled`, `dream_milestone`, `transaction_logged`, `learning`, `broken_promise`, `undo`, `day_closed`. Two new values needed: `miss_penalty` and `honesty_bonus`.
- `xp_log` has a partial unique index `xp_log_once_per_task_reason (task_id, pillar, reason) where task_id is not null and reversed_at is null`. A `missed_tasks` table keyed by a separate id (not task_id) will guard idempotency, since one missed-task record per task is the right model.
- `EventLike.status` in TypeScript is `"upcoming" | "done" | "cancelled"` — must add `"missed"`.
- `TaskStatus` in `src/features/xp/xp.ts` is `"pending" | "done" | "skipped" | "cancelled"` — must add `"missed"`.
- MCP tools for slips follow: Zod schema → repo function → `ok(await withMode(...))` → `toolError(...)`. The new `mark_missed` tool will mirror this exactly.
- Reviews (`reviews.repo.ts`) already pull slips; misses need to be pulled from the new `missed_tasks` table in the same query.
- `database.types.ts` is generated by `bun run db:types` after the migration runs.
- Build: `bun run typecheck` (`next typegen && tsc --noEmit`). Tests: `bun test src`.

## Key design decisions

- **`missed_tasks` table, not a column**: Reason, penalty, and honesty flag are rich data that deserve their own table, mirroring the `slips` table structure. A task can only be missed once (unique on `task_id`), but the table is its own source of truth rather than a flag on `tasks`.
- **`miss_penalty` and `honesty_bonus` as separate `xp_reason` values**: The existing idempotency index on `xp_log` will prevent double-payment per `(task_id, pillar, reason)`. Two distinct reasons are needed so the penalty row and bonus row can coexist without collision.
- **Penalty split across the task's own pillar weights; bonus always to `character`**: Mirrors how `ignoredNeedDeduction` works — penalty uses task's `PillarWeight[]`. Honesty is always flat `+2` to `character`.
- **`self_reported` boolean on `missed_tasks`**: Distinguishes user-triggered `mark_missed` (bonus eligible) from a future automated catch (no bonus). The new DB function only ever writes `self_reported = true` — this field is the guard, not the call path.
- **No separate event version of the DB function**: Events and tasks have different tables but the XP mechanism is identical; a single `record_miss` DB function handles both by accepting either `p_task_id` (tasks) or `p_event_id` (events), exactly one required.
- **Penalty amount**: `base_xp * 0.5` (matching `ignoredNeedPenalty`). Honesty bonus: 2 flat to Character (matching `transactionLogXp`). These satisfy "penalty > bonus always" for any `base_xp ≥ 1` (min penalty = 1 > 2 only for base_xp ≥ 4, but the minimum task XP in the app is 5, so penalty ≥ 3 > 2). Record these as constants in `src/shared/config.ts`.
- **Events with `missed` status stop blocking time / showing as upcoming**: `blockOn` and `upcoming` in `events.ts` check `status === "upcoming"` — a missed event naturally falls out of both.

- [ ] 1. **DB migration — `20261115090000_missed_tasks.sql`**

  Add `'missed'` to `task_status` enum; add `'missed'` to `events.status` check constraint; add `'miss_penalty'` and `'honesty_bonus'` to `xp_reason` enum; create `missed_tasks` table; create `record_miss` DB function.

  **`task_status` enum**: `ALTER TYPE public.task_status ADD VALUE IF NOT EXISTS 'missed';`

  **`events.status` check constraint**: Drop old constraint, add new one including `'missed'`.

  **`xp_reason` enum**:
  ```sql
  ALTER TYPE public.xp_reason ADD VALUE IF NOT EXISTS 'miss_penalty';
  ALTER TYPE public.xp_reason ADD VALUE IF NOT EXISTS 'honesty_bonus';
  ```

  **`missed_tasks` table** (composite `(id, user_id)` FK pattern, append-only semantics):
  ```
  id uuid PK default gen_random_uuid()
  user_id uuid NOT NULL references auth.users ON DELETE CASCADE
  task_id uuid references public.tasks(id) ON DELETE CASCADE  -- null for events
  event_id uuid references public.events(id) ON DELETE CASCADE  -- null for tasks
  reason text NOT NULL check (char_length(reason) between 1 and 300)
  penalty_xp integer NOT NULL
  honesty_xp integer NOT NULL  -- 0 when not self-reported
  self_reported boolean NOT NULL default true
  at timestamptz NOT NULL default now()
  CONSTRAINT one_source CHECK ((task_id IS NULL) != (event_id IS NULL))
  CONSTRAINT task_missed_once UNIQUE (task_id)
  CONSTRAINT event_missed_once UNIQUE (event_id)
  ```
  RLS: enable, `revoke all from anon, authenticated`, `grant select, insert on … to authenticated`, policy `"owner can read"` and `"owner can insert"` using `auth.uid() = user_id`.

  **`record_miss` DB function**: `SECURITY INVOKER`, `set search_path = ''`, revoke from `public, anon`, grant to `authenticated`.
  - Params: `p_task_id uuid`, `p_event_id uuid`, `p_reason text`, `p_penalty_entries jsonb`, `p_honesty_entries jsonb`, `p_self_reported boolean`.
  - Sets `tasks.status = 'missed'` (when `p_task_id` given) OR `events.status = 'missed'` (when `p_event_id` given); inserts `missed_tasks` row; calls `public.award_xp(p_penalty_entries || p_honesty_entries)`.
  - Returns `jsonb` with `result`: `'recorded'`, `'already_missed'`, `'not_found'`.

  Files: `supabase/migrations/20261115090000_missed_tasks.sql`

  Verify: `bun run db:reset --local` completes without errors; `bun run db:test` passes all existing pgTAP suites.

- [ ] 3. **XP engine — `missedXp` function in `src/features/xp/xp.ts`**

  Add `'miss_penalty'` and `'honesty_bonus'` to the `XpReason` type union (mirrors the Postgres enum). Add `'missed'` to `TaskStatus`. Add two config constants to `EngineConfig.xp` in `src/shared/config.ts`: `missPenaltyShare` (default `0.5`) and `honestyBonus` (default `2`). Add the function:

  ```ts
  /**
   * XP entries for an explicit miss.
   * penalty: base_xp * missPenaltyShare (negative), split across the task's pillars.
   * honesty: flat honestyBonus (positive) to 'character', only when self-reported.
   * Penalty always exceeds honesty for any base_xp ≥ 1 (minimum task XP is 5).
   */
  export function missedXp(
    baseXp: number,
    weights: readonly PillarWeight[],
    selfReported: boolean,
    config: EngineConfig = currentConfig(),
  ): XpEntry[] {
    const penalty = entries(-scale(baseXp, config.xp.missPenaltyShare), weights, "miss_penalty");
    if (!selfReported) return penalty;
    const bonus: XpEntry = { pillar: "character", amount: config.xp.honestyBonus, reason: "honesty_bonus" };
    return [...penalty, bonus];
  }
  ```

  Files: `src/features/xp/xp.ts`, `src/shared/config.ts`

  Verify: `bun test src/features/xp` — existing tests still pass. No new tests yet; they come in step 5 with the repo.

## Cross-cutting concerns flagged

1. **`database.types.ts` must be regenerated after the migration** (step 2). Without this, TypeScript won't accept `'missed'` on `task_status` or `'miss_penalty'` on `xp_reason`, and every subsequent step's typecheck will fail.

2. **`xp_log` idempotency index**: The existing `xp_log_once_per_task_reason` index is `(task_id, pillar, reason) where task_id is not null and reversed_at is null`. It will prevent a second `miss_penalty` for the same task on the same pillar, making `record_miss` safe to retry. No index change needed.

3. **`missed` tasks are frozen**: Like `done` tasks in `tasks.repo.ts`, a `missed` task should not be completable. Add `task.status === 'missed'` to the early-return guard in `completeTask` in `tasks.repo.ts` (return `{ result: 'already_done', title }` or a new `'missed'` result — returning `'already_done'` is the simplest and most consistent approach, since the task is in a terminal state). This is a one-line guard before the `complete_task` RPC call.

4. **Habits and routine steps**: They are ordinary `tasks` rows with `series_id` and `routine_id`. `mark_missed` takes any `task_id`, so it works for all three without special-casing. The tool description already calls this out.

5. **Events vs `update_event`**: The `changeEvent` repo function's `action` param doesn't include `'missed'`; this is correct by design. `record_miss` is the only path to `missed` status for events, so the XP flow is always enforced.

6. **`done_at_matches_status` check constraint**: `events` may have a constraint tying `done_at` to status `'done'`. The new `missed` status won't set `done_at`, so there's no conflict — but verify the events table has no such constraint that would need updating. (The `tasks` table has `done_at_matches_status check ((status = 'done') = (done_at is not null))` — adding `'missed'` to `task_status` is safe; missed tasks won't have a `done_at`.)
