## The University Course Standard (Mandatory Module Structure)

Every module note written under this course must follow this 5-part university lecture standard so that **anyone with zero prior background** can read and understand it:

1. **Section 1: Real-World Motivation ("Why Does This Exist?")**
   - Explain the limitation of simpler methods/structures.
   - Use relatable physical analogies (e.g. locker rooms, coat checks, folder trees, family trees).
   - Give 2-3 real production software examples (e.g. databases, DOM, web routing).

2. **Section 2: Intuitive Visual Breakdown & Plain-English Terminology**
   - Provide clear ASCII or Markdown diagrams showing the concept.
   - Include a **Plain-English Glossary Table** translating jargon into simple everyday terms.

3. **Section 3: Step-by-Step Technical Deep Dive & Line-by-Line Code**
   - Introduce formal properties step-by-step without skipping steps.
   - Provide clean Python/Pseudocode implementations with line-by-line annotations explaining *what* each line does and *why*.

4. **Section 4: Production Tradeoffs & Edge Cases**
   - Tabulate Big-O time and space complexity (Best, Average, Worst).
   - Detail common pitfalls, traps, and failure modes (e.g. off-by-one errors, degenerate trees, memory leaks).

5. **Section 5: Check Your Understanding (University Self-Assessment)**
   - Include 2-3 conceptual questions with collapsible `<details>` answers so the student can test their understanding immediately.
